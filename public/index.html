What it does

45 tools covering the whole Coolify platform, built around safety and context efficiency.

Asks before it hurts

Destructive operations — stop all apps, bulk env updates, resource deletes — require explicit human confirmation with a calculated blast radius.

Secrets stay hidden

Environment variables come back masked as ***. Revealing a single value is a separate, deliberate request. Private keys are never returned.

Fits in the context window

Lists return compact summaries — 90 to 99% smaller than raw API responses. Full details are fetched on demand.

Multi-instance fleet

Manage several Coolify installations from one connection. Every tool takes an instance name; instance: "all" fans out across the fleet.

Multi-tenant

Sign in with GitHub or Google, link your own Coolify, and get an isolated MCP connection. Your instance is never visible to another tenant.

Built-in docs search

An embedded full-text index of the Coolify documentation, searchable as a tool. No round-trip to an external service.

Set it up

Three steps, in order.

  1. Add the connector. Paste this endpoint into your assistant: https://coolify.mctl.ai/mcp
    In claude.ai: Customize → Connectors → "+" → Add custom connector, paste the URL, then Add.
    In ChatGPT: Settings → Apps & Connectors → Advanced settings → Developer mode, then back in Apps & Connectors → Create, paste the URL as the connector URL.
    In Claude Code or another MCP client: claude mcp add --transport http coolify https://coolify.mctl.ai/mcp
  2. Sign in with GitHub or Google. Happens automatically on the first Connect. Any GitHub or Google account can sign in. A consent screen names the client and what it is being granted.
  3. Link your Coolify. Open /enroll and enter your Coolify instance URL and API key (Settings → API → Generate Token). The page tests the credentials against your instance before saving them. If your Coolify has "Allowed API IPs" enabled, the egress addresses are shown on the enrolment page.

Your data on this server

We are transparent about what we store, what we can see, and what we cannot undo.

What is stored?

Your Coolify API token is stored in HashiCorp Vault (KV v2) under a dedicated mount. The path is keyed by the SHA-256 hash of your identity provider and user ID — it does not reveal your login or email. Each write enforces max_versions: 1, so Vault does not accumulate old versions.

Can the platform operator see my Coolify token?

Yes, technically. This is a self-hosted platform, not a zero-knowledge vault. The operator has administrative access to the Vault cluster and can read any stored token in plaintext. This is the same trust model as any managed service where the infrastructure is controlled by the operator. We are transparent about this because we think you should know.

Can another tenant reach my instance?

No. Every request builds a fresh registry from the calling tenant's own Vault record. Two tenants never share a registry. Outbound connections are guarded against SSRF (private IP blocklist, DNS pinning) and each tenant gets a pinned HTTP dispatcher that prevents DNS rebinding.

What is masked from AI clients?

Environment variable values return as ***. Revealing one requires an explicit reveal: true on a single named key. Private SSH keys are never returned. Container logs are wrapped in a cryptographic nonce boundary to defend against prompt injection.

How do I delete my data?

Open /enroll and click "Unlink everything and delete the stored tokens." This uses Vault destroy (hard delete), not delete (soft tombstone). All versions of your record are permanently removed. Revocation takes effect immediately.

Does it phone home?

Zero telemetry, zero analytics, zero phone-home. The only outbound connections go to the Coolify instances you linked and, optionally, a one-time documentation index refresh from coolify.io.

Questions

What Coolify versions are supported?

Coolify v4.0 through v4.3. The server tracks API changes across versions and the tool documentation notes where endpoints differ. get_version checks compatibility on every connection.

Can an assistant delete my apps on its own?

No. Destructive operations require explicit human confirmation via the MCP elicitation protocol. The blast radius is calculated and displayed; if the estate changes before you confirm, the ticket is invalidated. In read-only mode (MCP_READONLY), writes are disabled entirely.

Can I run it locally instead?

Yes. The upstream npx @masonator/coolify-mcp runs in stdio mode on your machine. Your token stays local. This hosted instance adds multi-tenancy, Vault storage, and OAuth 2.1 for remote MCP clients.
